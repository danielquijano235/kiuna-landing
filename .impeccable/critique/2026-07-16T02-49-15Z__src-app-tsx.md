## Anti-Patterns Verdict

**LLM assessment:** Partial. The site is genuinely above generic AI-SaaS baseline thanks to the real two-accent discipline (cyan/amber never mix), a bespoke bubble/spark particle system (not templated glassmorphism), and the absence of the hero-metric-gradient pattern PRODUCT.md names explicitly. Three "default scaffolding" tells remain: (1) every section opens with an identical uppercase-tracked kicker; (2) three unrelated content groups (differentiators, verticals, process) reuse the same amber 01-04 numeral index — individually rule-compliant, but the repeated pattern reads as templated once noticed; (3) the Verticales grid is 3 visually identical cards in internal anatomy.

**Deterministic scan:** `detect.mjs` ran clean on `App.tsx`/`index.html` but found 37 findings in `styles.css` (exit 2): 1 gradient-text (line 897, `.step-number` — confirmed real, and it's the one documented/permitted exception in DESIGN.md), 1 undocumented color (`#a5dbf3`, line 281), 9 border-radius values outside the DESIGN.md scale, 26 font-size values outside the documented scale. No false positives identified — DESIGN.md defines a real, narrow scale, so this is genuine drift.

**Where LLM and detector agree:** both point at the same underlying issue — the documented design system is more disciplined than its implementation. The detector quantifies token drift (35 out-of-scale values); the design review independently found the visible symptom: the "Display" typography role (the system's largest, `clamp(3.5rem,9vw,6.6rem)`) is defined at `styles.css:404-415` but overridden by a more specific rule at `styles.css:700-706` — it likely never renders anywhere. Dead CSS / doc drift.

**Visual overlays:** not available this session (no browser tool exposed); no fabricated signal reported.

## Overall Impression

A landing with a genuinely considered visual identity — not the typical purple-blue gradient with identical cards — but it weakens exactly at the highest-stakes moment: it asks the visitor for contact info without showing a single number from the proof PRODUCT.md says is available (+50 negocios automatizados, +$100M generados). The biggest opportunity isn't aesthetic, it's trust: the copy promises measurable results ("sin relleno", "medible desde el día uno") but shows no measurement.

## What's Working

1. The Two-Accent + One-Serif discipline is genuinely honored in code — cyan and amber never collide on one element, and the amber numeral gradient is exactly DESIGN.md's one permitted exception.
2. The bubble/spark particle layer is a legitimately bespoke interaction — hue-cycling pointer sparks with a capped, decaying particle count, not a copy-pasted template effect.
3. Kiuna Academy as a secondary CTA gives the "curious, not ready to buy" audience (named explicitly in PRODUCT.md) a legitimate lower-commitment exit ramp instead of forcing everyone toward the same high-stakes form.

## Priority Issues

**[P0] Missing social proof that PRODUCT.md says exists**
- Why it matters: PRODUCT.md lists "+50 negocios automatizados" and "+$100M en ingresos generados" as ready-to-use proof, but neither appears in `App.tsx`. This is exactly the evidence missing at belief-ladder step 2 ("Kiuna no vende demos bonitas, construye sistemas medibles").
- Fix: a restrained proof strip using amber numerals (the system's own "counted/proven" accent) near Differentiators or just above the contact form — not the banned hero-metric-gradient template.
- Suggested command: /impeccable distill

**[P1] CTA promises scheduling, delivers a contact form**
- Why it matters: "Agendar diagnóstico"/"Agendar llamada" promise a scheduling action; clicking only reaches a form ending in "te respondemos por correo pronto" — no calendar, no committed response time. Direct match-between-system-and-real-world violation on the primary conversion action.
- Fix: wire a real scheduling widget behind the CTA, or rewrite copy ("Cuéntanos tu caso"/"Solicita tu diagnóstico") and add a concrete commitment ("te respondemos en menos de 24h") next to submit.
- Suggested command: /impeccable clarify

**[P2] No prefers-reduced-motion support, despite PRODUCT.md claiming it exists**
- Why it matters: zero `@media (prefers-reduced-motion)` rules in the project. Hero parallax, beamFloat, scanCard, liftCard, and the bubble/spark system all run continuously and unconditionally — real vestibular-discomfort risk, contradicts PRODUCT.md's own accessibility claim.
- Fix: gate continuous/pointer animations behind `@media (prefers-reduced-motion: no-preference)` with a static fallback.
- Suggested command: /impeccable harden

**[P2] Mobile hero buries the primary CTA under a decorative widget**
- Why it matters: at ≤1080px, `.hero-grid` reorders to "copy" "stage" "cta" — the non-interactive `.hero-stage` card (redundant with Verticales) sits between hero copy and the "Agendar diagnóstico" button, adding scroll cost exactly where speed matters most for a distracted mobile visitor.
- Fix: reorder to "copy" "cta" "stage" on mobile, or drop the stage card on small viewports.
- Suggested command: /impeccable layout

**[P3] Repeated 01-04 numeral/kicker pattern across sections, plus 35 token values outside the documented scale**
- Why it matters: individually rule-compliant, but the aggregate pattern is exactly what PRODUCT.md's "distinción máxima" principle asks to avoid; confirmed detector drift (26 font-size + 9 radius values) is the same underlying issue — the documented system is more disciplined than the shipped code.
- Fix: vary treatment in at least one group (e.g. drop the serif numeral from Proceso, which already has its own connecting line, reserving Iowan Old Style for Verticales only); pass over stray font-size/radius values to align them to the DESIGN.md scale.
- Suggested command: /impeccable adapt

**Casey (Mobile User):** Hits the buried-CTA issue directly. Every tap fires an 11-particle burst animation across the viewport — harmless but adds visual noise while moving fast.

**Skeptical pyme owner (project-derived persona):** Evaluating multiple AI vendors, receives credibility promises ("sin relleno") with nothing quantified to back them, no FAQ on price/timeline/what a "diagnóstico" call involves, and a CTA verb ("Agendar") overpromising relative to what clicking it does — a plausible bounce point right before the form.

## Minor Observations

- CLAUDE.md is stale: describes the contact form as clipboard-copy + mailto with no API call, but `handleSubmit` POSTs JSON to `https://api.web3forms.com/submit`.
- `.hero-pill` and `.hero-band`/`.hero-band-item` are fully styled (including a dedicated responsive treatment) but unreferenced in `App.tsx` — orphaned CSS from an earlier layout.
- `.form-note` has no `aria-live` region — screen reader users won't hear the submission outcome without manually navigating to it.
- Footer offers no secondary navigation for a visitor who scrolls to the bottom without converting.

## Questions to Consider

1. The proof numbers ("+50 negocios", "$100M") never made it onto the page — deliberate avoidance of the hero-metric-gradient pattern, or simply not wired in yet? Either way, where in the current funnel does a skeptical visitor find evidence before being asked for contact info?
2. "Agendar diagnóstico" reads as immediate scheduling, but the flow ends at a form with an unspecified reply window — is a real booking tool on the roadmap, or should the copy be rewritten today to match what the button does?
3. The amber 01-04 numeral index is used across three unrelated content groups — is that a deliberate unifying brand motif, or the default pattern this codebase reaches for whenever it needs to present a list?
